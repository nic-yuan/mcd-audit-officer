# 控制点台账

> 每个控制点 = 一条可程序化执行的测试。编号与 `scripts/audit_engine.py` 中的 `RULES` 一一对应。

---

## R01 · 价差异常

| 项 | 内容 |
|---|---|
| **控制目标** | 申报金额与麦当劳官方核价一致 |
| **风险** | 报销人虚报金额，审核方无独立比价基准 |
| **测试方法** | `calculate-price` 按同门店 + 同品项 + 同券组合重算应付总额，与申报金额比对 |
| **容差** | `max(绝对值 1.00 元, 基准价 × 2%)`，取大者 |
| **升级条件** | 虚报额 > 0 且 `abs(差额) >= max(20 元, 基准 × 20%)` → 升为**重大** |
| **降级基准** | 无官方核价时，退用订单实付金额；两者都无则不判定（不臆测） |
| **证据要求** | 订单号、核价来源、容差取值、订单数据源 |

**这是本工具最核心的控制点。** 传统报销审核的最大盲区就是审核人只能看票面，无法独立验证价格。`calculate-price` 提供了独立基准。

## R02 · 券未核销

| 项 | 内容 |
|---|---|
| **控制目标** | 账户可用券应在下单时充分使用 |
| **风险** | 该省没省，形成隐性浪费 |
| **测试方法** | `query-my-coupons` / `query-store-coupons` 取可用券，与订单已核销券集合比对 |
| **降噪约束** | ① 申报金额 < 40 元不判定；② 同一人同一天最多报一条 |
| **分级** | 一般 |

约束②是必要的：同一批券会在多笔订单上被重复计数，不约束会产生大量无意义缺陷，稀释底稿价值。

## R03 · 超预算

| 项 | 内容 |
|---|---|
| **控制目标** | 单笔 / 单人单日 / 部门单月不超标准 |
| **风险** | 费用失控，超标未经审批 |
| **测试方法** | 三级汇总后逐级比对，命中即报（按最严格层级） |
| **阈值** | 单笔 80 / 单人单日 150 / 部门单月 8000（均为默认，可配） |
| **分级** | 重要 |

## R04 · 串项

| 项 | 内容 |
|---|---|
| **控制目标** | 申报品项与订单实际构成一致 |
| **风险** | 虚增品项抬高金额；非麦当劳消费混入 |
| **测试方法** | `query-meal-detail` 取套餐构成与可替换项，与申报品项集合做差集 |
| **判定** | `申报品项 - 订单实际 ≠ ∅` 即命中 |
| **分级** | 重要 |

注意：套餐替换项会导致品项名不一致，需以 `query-meal-detail` 返回的可替换项为准做归一化。

## R05 · 重复报销

| 项 | 内容 |
|---|---|
| **控制目标** | 同一订单不得多次申报 |
| **风险** | 典型费用舞弊手法，人工极难发现 |
| **测试方法** | 申报表内按 `order_no` 分组，出现次数 > 1 即命中 |
| **分级** | **重大** |
| **整改要点** | 除个案追回外，必须判断是否为**系统性控制缺陷**——报销系统若缺少订单号唯一性校验，同样的漏洞会持续发生 |

这是唯一仅凭申报表自身就能发现的控制点，不需要外部数据。成本低、价值高。

## R06 · 非工时订单

| 项 | 内容 |
|---|---|
| **控制目标** | 下单时间落在允许时段内 |
| **风险** | 非工作时段消费混入公司费用 |
| **测试方法** | 订单时间与政策时段比对 |
| **默认时段** | 07:00–21:00（含早餐时段，避免误伤早餐场景） |
| **分级** | 一般 |
| **整改要点** | 若属加班用餐，应附加班审批；无审批按个人消费处理 |

---

## R07 · 超期申报

| 项 | 内容 |
|---|---|
| **控制目标** | 订单发生后规定天数内完成申报 |
| **风险** | 跨期报销，影响期间费用截止性 |
| **测试方法** | `claim_date - order_date` 与 `filing_window_days` 比对 |
| **默认时限** | 30 天 |
| **分级** | 一般 |
| **整改要点** | 跨期申报应调整至实际发生期间，属截止性测试范畴 |

---

## 覆盖不到的风险（不做虚假承诺）

以下不属于本工具的能力范围，需在底稿"局限"中说明：

- 发票真伪与税务合规性（需对接税务系统）
- 报销人与实际消费人是否一致（需身份与考勤数据）
- 是否存在拆单规避审批（需完整订单全量，本工具依赖用户提供申报表）
- 非麦当劳消费的混入（仅能发现"申报品项不在订单中"，无法发现"根本没在麦当劳消费"）
